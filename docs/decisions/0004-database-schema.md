# 0004 — Database schema

- **Status:** Accepted
- **Date:** 2026-09-24

## Context

PATHS keeps its canon data as YAML in `data/` (the source of truth). The API needs to query it: neighbourhoods, "the graph at time _t_", search, all filtered by the reader's spoiler cutoff. The original blueprint sketched one table per entity kind, with relationships pointing at any of them.

## Decision

**The database is a derived, disposable copy of `data/`.** `pnpm db:seed` validates the data, then replaces every row in a single transaction. Nothing is ever edited in the database directly.

Schema (PostgreSQL 18, Drizzle ORM, `packages/db/src/schema.ts`):

- **One `entities` table** for every kind, with the kind as an enum. That lets `edges.source_id` / `target_id` be **real foreign keys**, which isn't possible when relationships can point into any of eight tables.
- **Detail tables only where a kind has extra fields:** `characters` (born, died), `events` (start, end, seq), `memories` (start). Titans, locations and factions have none, so they get no empty tables.
- **`entity_names`** holds every name _and_ spelling variant as its own row, with its reveal chapter, so spoiler-safe search is a single `where revealed_in <= cutoff`.
- **`description_segments`** with a generated `tsvector` column for full-text search.
- **Pre-resolved time columns.** The seed resolves dates and event references into integer bounds (`life_*` on entities, `active_*` on edges, already clipped to both endpoints' lifetimes). "The graph at time _t_" then becomes a plain range comparison, the same rule graph-core uses.
- **Dated facts are stored as written** (JSON), so no citation or note is lost.
- **Edge IDs are a hash of (source, type, target, from)**, so the identity rule from `conventions/ids.md` is enforced by the primary key.
- **Search** uses `pg_trgm` (a GIN trigram index on `lower(name)`) for misspellings, plus substring matching. There's no separate search engine.
- **Migrations** are generated by drizzle-kit from the schema. CI fails if the schema and the committed migrations drift apart.

## Consequences

- ✅ Referential integrity is enforced twice: by the validator and by foreign keys.
- ✅ The SQL queries are tested against graph-core on the real dataset. The two implementations must agree.
- ✅ Re-seeding is safe at any time, so the tests reseed freely.
- ❌ Edge attributes that reference entities (`side`, `in`) live in JSON, so only the validator checks them, not a foreign key.
- ❌ Local development needs Docker for Postgres. `pnpm check` doesn't, because database tests run separately (`pnpm test:db`), and in CI.
